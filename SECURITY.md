# Security Policy

## Supported Versions

Security fixes are provided for the actively maintained branch and current release line.

| Version | Supported |
| ------- | --------- |
| master (latest) | :white_check_mark: |
| Current stable release | :white_check_mark: |
| Older releases | :x: |

## Reporting a Vulnerability

If you discover a security vulnerability, please report it privately.

- Open a private security report through [GitHub Security Advisories](https://github.com/zlatko-lakisic/omegacms/security/advisories/new).
- If advisory reporting is unavailable, open an issue with minimal details and request a private contact path.
- Do **not** post exploit details, proof-of-concept code, or sensitive configuration data in public issues.

### What to include

Please include as much of the following as possible:

- Affected component(s) and file/path references
- Vulnerability type and potential impact
- Reproduction steps or proof-of-concept
- Affected version/commit and environment details
- Suggested remediation (if available)

### Response expectations

- Initial triage response target: within **5 business days**
- Status updates target: every **7 business days** while actively investigating
- If accepted, a fix will be prepared and released as soon as practical
- If declined, we will provide rationale where possible

Thank you for helping keep OmegaCMS and its users secure.
